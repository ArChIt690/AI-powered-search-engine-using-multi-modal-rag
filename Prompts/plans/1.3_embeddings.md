# 1.3 Text Embeddings and Image Embeddings (CLIP): plan

> Approved plan, kept for reference.
> Later change during the build: the semantic splitter compares the two sentences before each gap with the two
> after it (non-overlapping windows), because the overlapping-window method cut one sentence late on real text.

## Context
v2 diagram boxes: **"Spark Streaming: Text Embeddings"** (Chunking → Text Embeddings → Metadata Enrichment) and
**"Spark Streaming: Image Embeddings (CLIP)"** (PICTURES → Image Embeddings → Metadata Enrichment).
1.1 produces `Document.pictures` (images, PDF charts, video frames); 1.2 produces text `Chunk`s. 1.3 turns both
into vectors: `Chunk.text_embedding` (384-dim) and `Chunk.image_embedding` (512-dim), which the Vector Database
(1.5) indexes and Hybrid Search (Part 2) queries. v2 note 6: these models run on our own server, not an API.
Spark jobs come in 1.6 (rule 3), so here I build the plain Python functions they will call.

## Library: `sentence-transformers` for both boxes (already installed, no new dependency)
| Box | Model | Output |
|---|---|---|
| Text Embeddings | `BAAI/bge-small-en-v1.5` (config `text_embedding_model`) | 384-dim, unit length |
| Image Embeddings (CLIP) | `clip-ViT-B-32` (new config `clip_model`) | 512-dim, unit length |

Also used, all already present: PyTorch (runs the models; CPU on this machine), Pillow (decodes `Picture.data`),
langchain-core (only the `Embeddings` interface). First run downloads ~130 MB (bge) + ~600 MB (CLIP) to the
Hugging Face cache.

## Files

**`infra/models.py`** (extend): `get_text_model()` and `get_clip_model()`, each `lru_cache`d so a model loads
once per process, next to the existing `get_whisper()`. Device via the existing `_device()` (cuda only when torch
confirms it works, else cpu). On load, check the model's dimension equals `text_embedding_dim` /
`image_embedding_dim` and fail with a clear error if config and model disagree.

**`ingestion/text_embed.py`**: `TextEmbedder`, a LangChain `Embeddings`:
- `embed_chunks(chunks) -> chunks`: fills `text_embedding`, batches of `embedding_batch_size` (32), normalized
- `embed_documents(texts)` / `embed_query(text)`: the LangChain interface. `embed_query` adds bge's query
  prefix (`text_query_instruction`, already in config), which bge wants on queries only, never on documents
- one instance serves Chunking (semantic splitting), Text Embeddings, and later Part 2/4 query embedding

**`ingestion/image_embed.py`**: `ImageEmbedder`:
- `embed_pictures(doc) -> list[Chunk]`: one `Chunk` per `Picture`, with `image_embedding`, `modality` from
  `Picture.modality` (`image` / `video_frame`), `page`, `timestamp`, `source`, and
  `metadata.content = "image" | "chart" | "frame"`
- each picture chunk's `text` is a short label so BM25 can still match it by file name, e.g.
  `"chart from report.pdf, page 3"`, `"video frame from talk.mp4 at 01:23"`. No invented captions
  (captioning isn't in the diagram)
- `embed_texts(queries)`: CLIP's text encoder, for Part 2's text-to-image kNN
- pictures decoded with Pillow, converted to RGB, embedded in batches; a picture that fails to decode is logged
  and skipped instead of failing the whole file

**`ingestion/chunking.py`**: replace `SemanticChunker` with our own `_semantic_split()` (the open decision in
Build_order). Same algorithm and same settings: split into sentences → embed each sentence with its neighbours
(buffer 1) via the passed `Embeddings` → cosine distance between neighbours → cut where distance ≥ the
`semantic_breakpoint_percentile` (90th) → then the existing min-size merge and oversize re-split.
About 30 lines with numpy. Removes the `langchain-experimental` / `langchain-community` imports (both being retired)
and their deprecation warnings; drop `langchain-experimental` from `pyproject.toml` if nothing else uses it.
The existing 1.2 semantic tests must still pass unchanged.

**`core/config.py`**: add `clip_model: str = "clip-ViT-B-32"`. Everything else already exists.

Both embedders take lists and return lists, so the 1.6 Spark jobs can run them per batch (`mapInPandas`) with
the model loaded once per worker.

## Tests
- **Unit (fast, fake models)** `tests/unit/ingestion/test_text_embed.py`, `test_image_embed.py`:
  vectors land on the right chunks, in order; batching; `embed_query` adds the prefix and `embed_documents`
  doesn't; picture chunks get the right modality/page/timestamp/label/content; a broken picture is skipped;
  empty inputs; dimension-mismatch error.
- **Real models** (marked `slow`, registered in `pyproject.toml`, run with `pytest -m slow`):
  384/512 dims and unit length; bge ranks a relevant sentence above an unrelated one; CLIP text
  "a red square" is closer to a red image than a blue one; our semantic splitter cuts real mixed-topic text
  at the topic change.
