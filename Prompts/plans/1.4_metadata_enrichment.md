# 1.4 Metadata Enrichment: plan

## Context
v2 diagram: **Spark Streaming: Text Embeddings** and **Spark Streaming: Image Embeddings (CLIP)** both flow into
**METADATA ENRICHMENT**, which flows into the **VECTOR DATABASE**. So enrichment runs *after* both embedding boxes,
on every chunk (text, table, record, transcript, image, chart, frame), and gives each one:
- a stable **id** (becomes the Elasticsearch `_id` in 1.5)
- a consistent set of **typed metadata fields**, which Part 2's Metadata Filtering and the frontend's citations
  depend on (PDF page, image, video timestamp)

No LLM calls (Build_order budget: ingestion = 0). No invented summaries or keywords, because the diagram doesn't have them.

## What each chunk gets

| Field | Where it comes from | Used for |
|---|---|---|
| `id` = `<doc_id>-<chunk_index>` | enrichment | ES `_id`; citations |
| `doc_id` | SHA-1 of the file's absolute path (first 16 hex chars) | re-ingesting the same file gives the same ids, so 1.5 replaces it instead of duplicating it |
| `chunk_index` | position in the document (text chunks first, then pictures) | ordering, ids |
| `file_name`, `file_type` | `Document.source`, `Document.file_type` | filtering ("only PDFs"), display |
| `modality` | already on the Chunk | filtering (text / image / video_transcript / video_frame) |
| `content` | already set by Chunking / Image Embeddings | text / table / record / image / chart / frame |
| `page`, `timestamp` | already on the Chunk | citations (PDF page, video time) |
| `section` | already set for Markdown headings | citations, filtering |
| `title` | PDF title if present, else the file name without extension | display |
| `author` | PDF metadata | filtering |
| `created` | PDF creation date / photo EXIF date / video creation time (from 1.1) | date filtering |
| `file_modified` | the file's last-modified time, when the file exists | date filtering |
| `ingested_at` | current UTC time | date filtering, debugging |
| `page_count`, `duration_s`, `language` | file-level info from 1.1, copied onto each chunk | filtering, display |

## Implementation
**`schemas/chunk.py`**: add a `ChunkMetadata` Pydantic model with the fields above, all typed and optional
(dates as ISO strings, page and chunk_index as int, timestamp and duration_s as float). This is the one source
of truth for:
- the Elasticsearch field mapping in 1.5 (typed `metadata.*` fields)
- Part 2's Metadata Filtering

It prevents one file writing `page: "3"` and another `page: 3`, which would break filtering. `Chunk.metadata`
stays a dict (`ChunkMetadata(...).model_dump(exclude_none=True)`), so nothing else changes.
Also remove `Modality.EVAL`: v2 note 4 says eval results never enter ingestion, and nothing uses it.

**`ingestion/enrichment.py`**: one plain function, which the Spark job in 1.6 will call:
```python
def enrich(doc: Document, chunks: list[Chunk]) -> list[Chunk]
```
- sets `id` and fills the metadata for every chunk
- keeps what earlier boxes already set (`content`, `section`, embeddings)
- validates the result through `ChunkMetadata`
- a document with 0 chunks returns `[]`

**One wording fix in `Prompts/Build_order.md`** (which I wrote): 1.4 currently says enrichment adds "the index
version the Cache layer uses". Tagging every chunk isn't needed for that. The Cache layer only needs one global
counter that 1.5 bumps after each successful write. So 1.4 won't store it per chunk, and I'll correct the
sentence (1.5 already describes the bump).

## Tests
`tests/unit/ingestion/test_enrichment.py`:
- ids are unique, in order, and the same across two runs; different files get different `doc_id`s
- PDF chunks get title, author, created, page_count and page
- picture chunks (image, chart, frame) are enriched too; video chunks get `timestamp`, `duration_s` and `language`
- the title falls back to the file name; `file_modified` is set when the file exists and skipped when it doesn't
- existing `content` and `section` values and the embeddings are kept
- all metadata types are valid (`ChunkMetadata` round-trips)
